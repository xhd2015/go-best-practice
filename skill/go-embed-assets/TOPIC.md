# go-embed-assets — embed placeholders + release hydrate

How to ship **generated** static assets (SPA `dist/`, Chrome extension trees,
etc.) with Go `//go:embed` so that:

1. **Bare `go install` / module consumers always compile** (no
   `pattern …: no matching files found`).
2. **Real assets** come from a fat local build and/or **version-pinned
   GitHub release archives** at runtime.

Worked example: **browser-agent** (`docs/assets-hydrate.md`, embed under
`browseragent/embedded/`, `script/github/release-assets`,
`browser-agent assets ensure|status`).

## Problem

- `//go:embed <dir>` or `//go:embed dir/**` requires matching files **at
  compile time**.
- Generated trees are usually **gitignored** (large, regenerated by
  vite/npm/bundle scripts).
- A Go **module zip** is the git tree at the tag. If the embed path is
  missing entirely, **every importer** fails — including downstream tools
  that only `go install` your package (they never run your local frontend
  build).

**Anti-pattern:** `//go:embed dist` with all of `dist/` gitignored and
nothing committed under that path. Clean clones and module cache builds
fail with:

```text
pattern dist: no matching files found
```

## Decision tree

| Situation | Approach |
| --------- | -------- |
| Binary-only; never published for others to compile | Build assets before `go install` in your install script (still better to keep placeholders if anything is tagged). |
| Library / CLI module others `go get` or `go install` | **Layer 1 — placeholders in git** (required). |
| Need real UI after bare `go install` without Node | **Layer 4 — runtime hydrate** from version-pinned release archives. |
| Official offline release binary | **Layer 3 — fat embed** via bundle/install before packaging the binary. |

## Layer 1 — Compile safety (always)

Keep every `//go:embed` root **non-empty in git**.

### Conduct

1. Choose embed roots, e.g. `pkg/assets/embedded/ui/` or
   `frontend/dist/` (name is product-specific).
2. Commit a tracked **`placeholder.txt`** under each root (short text is
   fine; document that the tree is incomplete).
3. **gitignore** generated files; **un-ignore** the placeholder:

```gitignore
# Generated payloads; only placeholder.txt is tracked so go install /
# module zip stay incomplete and runtime hydrate can download fat trees.
path/to/embed/**
!path/to/embed/placeholder.txt
```

4. Embed with a recursive pattern so the placeholder always matches:

```go
//go:embed embedded/ui/**
var embeddedUI embed.FS
```

Prefer `embedded/<kind>/**` over a bare directory name when you need
git to track only the placeholder while tools stage full trees next to it.

5. Optional **pre-commit** helper: if placeholders are missing, create
   them and `git add` them so embed roots never empty after a destructive
   bundle clean. (browser-agent: `go run ./script/git/pre-commit`.)

### Done when

```bash
# Clean tree: no Node/vite, only placeholders under embed roots
go build ./...
# or for a tiny consumer module that imports your package:
go install example.com/your-module@vX.Y.Z
```

Both succeed without a frontend build.

## Layer 2 — Completeness (fat vs placeholder)

Do not treat “embed compiles” as “UI is ready”.

### Conduct

1. Define **`EmbedComplete(kind)`** (or equivalent) over an `fs.FS`
   rooted at the asset tree.
2. Require **outstanding** non-empty files for that kind, for example:
   - **session-page / SPA:** real `index.html` (or equivalent) **and**
     built JS assets (e.g. under `assets/`), not only `placeholder.txt`.
   - **extension:** non-empty `manifest.json` and entry script
     (e.g. `background.js`).
3. Placeholder-only trees → **incomplete**.

Use completeness on:

- live `//go:embed` FS (is this binary fat?),
- on-disk dirs before install (should we auto-bundle?),
- local asset cache after download.

## Layer 3 — Fat local path (dev + release binaries)

### Conduct

1. **`bundle` script:** generate assets (vite/npm/copy fixtures) and
   **stage** them into the embed directories. Generated files stay
   gitignored; placeholders remain the only tracked files.
2. **`install` script:**
   - if on-disk embed is **incomplete** → run bundle,
   - optional `--force-bundle` to refresh even when complete,
   - then `go install` so the binary embeds the fat tree.
3. Run bundle with the same tooling you use in CI for release binaries.

### Done when

After `go run ./script/.../install` (or equivalent), the binary serves
real UI **offline** from embed (`source=embed`). No download required.

## Layer 4 — Runtime hydrate (thin / module embed)

When the binary was built with placeholders only (typical
`go install github.com/...@v…`), fill the gap at runtime.

### Resolve order

```text
1. Live embed complete?     → use embed   (source "embed")
2. Local asset-cache hit?   → use cache   (source "cache")
3. Else download archive    → write cache → use cache
```

Never use the GitHub **`latest`** tag for hydrate. Pin to the
**binary’s embedded version** (`VERSION.txt`, `ClientVersion()`, etc.).

### Cache layout (convention)

```text
# Prefer XDG when set:
$XDG_CACHE_HOME/<product>/asset-cache/<product>/<version>/<kind>/

# Default when XDG_CACHE_HOME is unset:
~/.cache/<product>/asset-cache/<product>/<version>/<kind>/
```

Example: `~/.cache/browser-agent/asset-cache/browser-agent/v0.2.0/session-page/`.

### Download URL (convention)

```text
{BaseURL}/v{version}/{product}_v{version}_{kind}.tar.gz
```

- **`BaseURL`:** typically
  `https://github.com/<org>/<repo>/releases/download`
  (override via env, e.g. `BROWSER_AGENT_ASSET_BASE_URL` or
  `<PRODUCT>_ASSET_BASE_URL`).
- **`version`:** normalized with a leading `v` (e.g. `0.2.0` → `v0.2.0`).
- **`kind`:** e.g. `session-page`, `extension`.

Implementation notes:

- Single-flight concurrent ensures (avoid half-written cache).
- Atomic write (temp dir + rename).
- Clear errors on HTTP 404 / network failure; do not mark incomplete
  cache complete.
- Operator CLI: `assets status` (embed + cache, no network),
  `assets ensure` (download if needed).

### Graceful degradation

If embed, cache, and network all fail, prefer a **minimal pure-Go
fallback** (or a clear error) over crashing the whole process, when the
product allows it.

## Layer 5 — Publish release assets

Hydrate only works if archives exist for that version.

### Conduct

1. On a release machine/CI: run **fat bundle** so embed dirs are complete
   on disk.
2. Pack each kind into archives whose basenames **exactly** match the
   runtime (`{product}_v{version}_{kind}.tar.gz`).
3. Upload to the GitHub release for tag `v{version}`
   (`gh release create` if missing, `gh release upload --clobber`).
4. Tag / binary version string and archive names must stay in lockstep.

browser-agent: `go run ./script/github/release-assets --out ./dist --version v0.2.0 [--upload]`.

### Done when

A machine with **placeholder-only** embed can run `assets ensure` (with
the right `*_ASSET_BASE_URL`) and get a **complete** cache for that
version.

## End-to-end picture

```text
                    git / go module
                           │
              ┌────────────▼────────────┐
              │  //go:embed …/**         │
              │  only placeholder.txt   │  ← always compiles
              └────────────┬────────────┘
                           │
         ┌─────────────────┼─────────────────┐
         ▼                 ▼                 ▼
   fat local build    incomplete embed   incomplete + network
   (bundle/install)   + complete cache   + ASSET_BASE_URL
         │                 │                 │
         ▼                 ▼                 ▼
      use embed         use cache      download release tar.gz
                                         → write cache → use
```

| Channel | What is shipped |
| ------- | --------------- |
| Git / module proxy | Source + **placeholders only** |
| GitHub Release assets | **Fat** trees as versioned `.tar.gz` |
| Official fat binary | Full `//go:embed` after local bundle |

## Conduct checklist

Copy for agents implementing this pattern:

- [ ] `placeholder.txt` committed under every `//go:embed` root
- [ ] gitignore ignores generated files; un-ignores placeholder
- [ ] Completeness check distinguishes placeholder vs fat tree
- [ ] Local install auto-bundles when on-disk embed is incomplete
- [ ] Release packs versioned archives with stable basenames
- [ ] Runtime resolve: complete embed → cache → download
- [ ] Version pin: binary version == release tag / archive path segment
- [ ] `go build` of a consumer that imports the package succeeds
      **without** bundling or Node

## Minimal code sketches

### Embed + complete check (illustrative)

```go
//go:embed embedded/ui/**
var embeddedUI embed.FS

func UIEmbedComplete() bool {
    // outstanding files for your product, e.g. index.html + assets JS
    // return false when only placeholder.txt is present
    return false // implement per kind
}
```

### Resolve preference (illustrative)

```go
func ResolveUI(version string, cfg DownloadConfig) (fs.FS, source string, err error) {
    if UIEmbedComplete() {
        return embeddedUI, "embed", nil
    }
    if CacheComplete(product, version, kind) {
        return os.DirFS(CacheDir(...)), "cache", nil
    }
    dir, err := EnsureAsset(ctx, product, version, kind, cfg) // GET tar.gz
    if err != nil {
        return nil, "", err
    }
    return os.DirFS(dir), "cache", nil
}
```
